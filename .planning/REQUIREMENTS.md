# Requirements: Private Classifieds (Частные объявления)

**Defined:** 2026-11-18
**Core Value:** Объявление частного лица находят покупателя — оно не тонет среди коммерческих предложений.

## v1 Requirements

Requirements for initial release. Each maps to roadmap phases.
Источники: docs/PRD.md (явные требования) + `.planning/research/FEATURES.md` (table stakes, которых нет в PRD — включены автоматически в auto-режиме).

### Authentication

- [ ] **AUTH-01**: Пользователь может зарегистрироваться с e-mail и паролем
- [ ] **AUTH-02**: Пользователь подтверждает e-mail по ссылке из письма до получения доступа к публикации
- [ ] **AUTH-03**: Пользователь может войти и остаётся в системе между визитами
- [ ] **AUTH-04**: Пользователь может восстановить пароль по ссылке из e-mail
- [ ] **AUTH-05**: Пользователь может выйти из системы

### Profiles

- [ ] **PROF-01**: Пользователь может заполнить профиль с обязательными полями: имя, телефон для связи, e-mail
- [ ] **PROF-02**: Телефон и e-mail продавца видны только аутентифицированным пользователям и по явному действию («показать контакты»)

### Admin Catalogs

- [ ] **ADMN-01**: Администратор может управлять иерархическим рубрикатором: создавать, переименовывать и перемещать категории (с защитой от циклов; удаление категории с активными объявлениями запрещено)
- [ ] **ADMN-02**: Администратор может управлять справочником городов: добавлять, переименовывать, объединять дубли

### Listings

- [ ] **LIST-01**: Пользователь может создать объявление с обязательными полями: город, категория, заголовок (≤128 символов), описание (≤512 символов), цена
- [ ] **LIST-02**: Пользователь может редактировать свои объявления
- [ ] **LIST-03**: Пользователь может удалить своё объявление
- [ ] **LIST-04**: Пользователь может опубликовать объявление; одновременно активно не более 10 (лимит проверяется атомарно на стороне БД)
- [ ] **LIST-05**: Пользователь может снять объявление с публикации; снятое объявление удаляется из базы данных
- [ ] **LIST-06**: Пользователь может сохранить объявление как черновик (не публикуется, не виден в поиске, не считается в лимите 10)

### Listing Photos

- [ ] **PHOTO-01**: Пользователь может прикрепить к объявлению минимум одно фото (загрузка, хранение вне БД, отображение на странице объявления и в выдаче)
- [ ] **PHOTO-02**: Фото удаляются вместе с объявлением (нет осиротевших файлов после снятия с публикации)

### Public Pages

- [ ] **PAGE-01**: Покупатель может открыть страницу объявления по SEO-дружественному URL (город/категория/заголовок), включая анонимно (без регистрации)
- [ ] **PAGE-02**: Покупатель может открыть страницу продавца с его активными объявлениями
- [ ] **PAGE-03**: Все страницы работоспособны на мобильных устройствах (responsive web)

### Search

- [ ] **SRCH-01**: Пользователь может искать объявления полнотекстовым поиском по заголовку и описанию (русская морфология)
- [ ] **SRCH-02**: Пользователь может фильтровать выдачу: категория (включая поддерево), город, диапазон цены
- [ ] **SRCH-03**: Пользователь может сортировать выдачу по дате и по цене (возрастание/убывание)
- [ ] **SRCH-04**: Выдача paginate'ится (без деградации на глубоких страницах)

### Messaging

- [ ] **MSG-01**: Пользователь может написать сообщение продавцу по объявлению (диалог привязан к объявлению; сообщение ≤512 символов)
- [ ] **MSG-02**: Пользователь может читать свои диалоги и видеть непрочитанные сообщения
- [ ] **MSG-03**: Пользователь получает e-mail уведомление о новом сообщении со ссылкой на диалог
- [ ] **MSG-04**: Диалог переживает удаление объявления (снапшот заголовка/цены; пометка «объявление удалено»)
- [ ] **MSG-05**: Мессенджер защищён базовым анти-абьюзом: лимиты частоты отправки, серверная блокировка доставки заблокированным пользователям

### Moderation

- [ ] **MODR-01**: Пользователь может пожаловаться на объявление или сообщение; жалобы попадают в очередь модерации
- [ ] **MODR-02**: Администратор может скрыть/снять с публикации чужое объявление
- [ ] **MODR-03**: Администратор может заблокировать пользователя (запрет публикации и доставки сообщений)
- [ ] **MODR-04**: Действия администратора фиксируются в журнале (audit log)

## v2 Requirements

Deferred to future release. Tracked but not in current roadmap.

### Engagement

- **FAV-01**: Пользователь может добавить объявление в избранное (триггер: повторные визиты покупателей)
- **SAVE-01**: Пользователь может сохранить поисковый запрос и получать уведомления о новых объявлениях по подписке
- **VIEW-01**: Продавец видит счётчик просмотров своего объявления
- **SOLD-01**: Продавец может пометить объявление «продано» одним действием (UX-обёртка снятия с публикации)

### Messaging Enhancements

- **MASK-01**: Маскировка телефонов/ссылок в чате до установления контакта (триггер: первые случаи парсинга/спама)
- **REAL-01**: Уведомления о сообщениях в реальном времени (WebSocket) вместо email-only

## Out of Scope

Explicitly excluded. Documented to prevent scope creep.

| Feature | Reason |
|---------|--------|
| Коммерческие аккаунты (магазины, витрины) | Прямо противоречит Core Value — вернёт проблему вытеснения частников |
| Платное продвижение (boost, featured, поднятие в топ) | Коммерциализация = проблема, которую продукт решает; равная видимость — фича |
| Платное размещение / подписки для частников | Сценарий деградации Avito: сокращение бесплатного → отток частников |
| Внутренние платежи, эскроу, доставка | Финансовая/юридическая сложность другого порядка; меняет продукт из classifieds в e-commerce |
| Отзывы и рейтинги участников | Холодный старт (новичок = «подозрительный»); карательный UX для разовых продаж |
| Аукционы / торг | Classifieds = фиксированная цена; торг естественно происходит в переписке |
| Поиск по радиусу (гео) | Требует координат/геокодинга; справочник городов достаточен для MVP (пересмотр в v2+) |
| Мобильные приложения (iOS/Android) | Web-first; responsive покрывает 75%+ мобильного трафика; удваивает стоимость |
| AI-рекомендации / AI-модерация | Преждевременно на greenfield без данных; простые правила + жалобы достаточны до PMF |
| Автоподнятие / репосты объявлений | Скрытое продвижение; лимит 10 естественно ограничивает (прецедент KSL) |
| SMS-верификация телефона | Только если скам станет системным (research: right-sizing верификации) |
