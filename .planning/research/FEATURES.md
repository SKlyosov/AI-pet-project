# Feature Research

**Domain:** Веб-сервис частных объявлений (private classifieds marketplace)
**Researched:** 2025-01-14
**Confidence:** MEDIUM

## Feature Landscape

Контекст проекта принципиально важен для категоризации: **вся суть продукта — «только частные лица, без коммерциализации»**. Ряд «стандартных» функций индустрии (платное продвижение, бизнес-аккаунты) для этого проекта являются **анти-фичами по определению**, а не упущениями. Исследование опирается на анализ функционала Avito, Craigslist, OLX, Gumtree, Kleinanzeigen, лучшие практики marketplace-мессенджинга (TalkJS, PubNub), UX-исследования фильтров и поиска (NN/g, Baymard, Smashing), а также на жалобы пользователей коммерциализированных площадок (Avito: сокращение бесплатного лимита до 4 объявлений/месяц, спам дилеров фейковыми объявлениями, платные алгоритмы продвижения).

### Table Stakes (Users Expect These)

Функции, которые пользователи считают само собой разумеющимися. Их отсутствие = «сервис сломан». Колонка «В PRD» отмечает, покрыта ли функция PRD (docs/PRD.md) — пробелы станут вопросами для фазы requirements.

| Feature | Why Expected | Complexity | Notes |
|---------|--------------|------------|-------|
| Регистрация и аутентификация (email + пароль, восстановление пароля) | Невозможно иметь «свои» объявления и сообщения без аккаунта; PRD задаёт роли, но не описывает флоу | LOW | **Не описана в PRD** — только роли. Требует уточнения при requirements: подтверждение email, сброс пароля |
| Подтверждение e-mail при регистрации | Базовая защита от фейковых аккаунтов и спама; стандарт индустрии (71.5% платформ ограничиваются хотя бы этим) | LOW | **Не описано в PRD.** Минимальный уровень верификации, соответствующий стадии продукта |
| Listing CRUD (создание/редактирование/удаление) | Ядро продукта; ожидание №1 любого classifieds-сервиса | MEDIUM | **В PRD.** Обязательные поля: продавец, город, категория, заголовок ≤128, описание ≤512, цена |
| Фотографии объявления | «Картинка решает» — на всех площадках клик в первую очередь получает объявление с фото; текст-only объявление выглядит подозрительно | MEDIUM | **НЕ описано в PRD** — крупнейший пробел. Настоятельно рекомендовать добавление (хотя бы 1 фото) на фазе requirements |
| Публикация/снятие с публикация, лимит ≤10 активных | Механика видимости объявления | MEDIUM | **В PRD.** Снятие с публикации = удаление из БД (hard delete, без архива). Лимит — конкурентное преимущество, см. Differentiators |
| Search по объявлениям | Покупатель приходит искать, а не browse вслепую | MEDIUM | **В PRD** (как «поиск чужих объявлений»), но без деталей: нужен полнотекстовый поиск по заголовку/описанию |
| Фильтры поиска: категория, город, диапазон цены | 80% пользователей в тестах Baymard применяют ценовой фильтр; фильтры ожидаются «всегда доступными» | MEDIUM | **НЕ описано в PRD** (заявлен только поиск). Категория — через навигацию по дереву, не чекбоксами (NN/g) |
| Сортировка результатов (дата, цена ↑/↓) | Стандарт de facto; без сортировки по дате «свежие» теряют смысл | LOW | **Не описано в PRD.** Для «равных условий» критична сортировка по дате без платных бустов |
| Пагинация / бесконечная прокрутка результатов | Без неё выдача нечитаема при любом заметном объёме | LOW | **Не описано в PRD.** Архитектурно важно при масштабе до 1M пользователей |
| Страница объявления (detail view) | Результат поиска должен куда-то вести: фото, описание, цена, продавец, кнопка «написать» | LOW | **Подразумевается PRD**, но явно не описана |
| Страница продавца («другие объявления пользователя») | Покупатель проверяет, кто продаёт; повышает доверие и глубину просмотра | LOW | **Не описано в PRD.** Дёшево на базе Listing CRUD + профиль |
| Профиль пользователя (имя, телефон, e-mail) | Продавец без имени/контактов не вызывает доверия | LOW | **В PRD.** Вопрос для requirements: виден ли телефон всем или передаётся через сообщения |
| Messaging (диалог покупатель↔продавец по объявлению) | «Написать продавцу» — основной CTA classifieds с эпохи Craigslist | MEDIUM-HIGH | **В PRD** (чтение/отправка, ≤512 символов). Вопросы: привязка диалога к объявлению, непрочитанные, список диалогов |
| Уведомления о новых сообщениях (email) | Без уведомлений мессенджинг мёртв: получатель не заходит на сайт «просто проверить» | MEDIUM | **НЕ описано в PRD** — критический пробел для Messaging. Минимум — email со ссылкой на диалог |
| Мобильная адаптивность (responsive web) | 75%+ трафика classifieds — мобильный; Google приоритизирует mobile-friendly | LOW | **Не описано в PRD** (web-first заявлен). Не приложение, а именно адаптивный веб |
| Публичные URL объявлений, дружественные к SEO | Органический поисковый трафик — главный канал бесплатных площадок; чистые URL (`/city/category/slug`) | LOW | **Не описано в PRD.** Дёшево сделать сразу, дорого переделывать потом |
| Жалоба на объявление/сообщение (report abuse) | Пользователи ожидают кнопку «пожаловаться»; без неё модерация вслепую | LOW-MEDIUM | **Не описано в PRD.** Модерация «по жалобам» — минимально достаточный уровень для старта |
| Admin: иерархический рубрикатор (дерево категорий) | Навигация по категориям — скелет classifieds с газетных времён | MEDIUM | **В PRD.** Требует валидации: нельзя удалять категорию с активными объявлениями / перенос вложенных |
| Admin: справочник городов | Локальность — суть жанра; фильтр «город» на нём и строится | LOW | **В PRD** |
| Admin: управление пользователями и контентом (базовое) | PRD даёт админу только каталоги; но кого-то должен банить спамера и скрывать запрещённый контент | MEDIUM | **Не описано в PRD** — пробел. Минимум: блокировка пользователя, снятие объявления с публикации |

### Differentiators (Competitive Advantage)

Конкурентные преимущества, прямо вытекающие из Core Value («объявление частного лица не тонет среди коммерческих»).

| Feature | Value Proposition | Complexity | Notes |
|---------|-------------------|------------|-------|
| Только частные лица — концепция продукта | Главная боль рынка подтверждена жалобами на Avito: частники вытеснены бизнес-аккаунтами и спамом дилеров | — (позиционирование) | Не функция, а рамка: каждая фича проверяется на «не ломает ли приватность площадки» |
| Лимит ≤10 активных объявлений на пользователя | Превентивный анти-спам: дилер физически не может залить сотнями фейковых объявлений выдачу (ровно то, на что жалуются на Avito) | MEDIUM | **В PRD.** Требует атомарной проверки лимита при публикации (race condition) |
| Никакого платного продвижения — равная видимость | Честная выдача: сортировка по дате/релевантности, без «поднятий», VIP-рамок и выделения цветом | LOW | **В PRD (Out of Scope).** Продаётся как фича: «у нас нельзя купить видимость» |
| On-platform messaging с маскировкой контактов | Телефон/e-mail/ссылки в чате скрываются до установления контакта — защита от спай-парсинга телефонов и скам-схем (паттерн Airbnb/Fiverr/TalkJS) | MEDIUM | **Частично в PRD** (мессенджинг есть, маскировка нет). Патент-фри реализация: regex-маскирование + «показать телефон на странице продавца» по желанию |
| Прозрачность правил: без скрытых алгоритмов | Пользователи Avito жалуются на непредсказуемые платные алгоритмы; «что опубликовал — то и видно, по дате» | LOW | Дешёвый дифференциатор: предсказуемая сортировка как обещание бренда |
| Бесплатность для частников | Против тренда индустрии (Avito: 4 бесплатных объявления/месяц в категории) | — (следствие бизнес-модели) | Монетизация не заявлена — и это осознанный выбор MVP |

### Anti-Features (Commonly Requested, Often Problematic)

Что сознательно НЕ строим. Защищает от scope creep и размывания концепции.

| Feature | Why Requested | Why Problematic | Alternative |
|---------|---------------|-----------------|-------------|
| Коммерческие аккаунты (магазины, витрины, прайс-листы) | «Пусть тоже продают — больше объявлений» | Прямо противоречит Core Value; вернёт проблему, которую решаем (частники утонут) | Строго нет. Бизнес-продавцы детектятся лимитом 10 и модерацией |
| Платное продвижение (boost, featured, выделение, поднятие в топ) | Стандартный запрос «как монетизировать» | Коммерциализация = решаемая проблема; подрывает доверие к честной выдаче | Нет никогда (в рамках этого продукта). Равная видимость как фича |
| Платное размещение / подписки для частников | Кажется лёгкой монетизацией | Avito-сценарий: сокращение бесплатного = отток частников, площадка деградирует в B2B | Бесплатно для частных лиц |
| Внутренние платежи, эскроу, доставка (аналог «Avito Доставка») | «Безопасная сделка» звучит продаваемо | Финансовая/юридическая сложность другого порядка; меняет продукт из classifieds в e-commerce; главный источник скам-жалоб на Avito | Сделка строго между сторонами; on-platform чат сохраняет «бумажный след» |
| Отзывы и рейтинги участников | Стандарт крупных маркетплейсов | Холодный старт (новичок без отзывов = «подозрительный»); рейтинговать частное лицо за разовую продажу — карательный UX; нагрузка на модерацию | Report/block + модерация администратором; доверие через подтверждённый email и историю объявлений |
| Аукционы / торг (bidding) | «Хочется продать дороже» | Classifieds = фиксированная цена; аукцион — другой продукт со своей сложностью | Цена в объявлении + торгов в переписке (естественным образом) |
| Гео-радиус поиск («в радиусе N км») | Удобно, есть у всех крупных | Требует координат/геокодинга; PRD использует справочник городов — проще и достаточнее для MVP | Фильтр по городу; радиус — в Future Consideration |
| Чат-боты, AI-рекомендации, AI-модерация 24/7 | Модный тренд 2025-2026 | Преждевременно на greenfield без данных; дорого; смещает фокус с ядра | Простые правила + жалобы; AI — после product-market fit |
| Мобильные приложения (iOS/Android) | «У всех есть» | PRD явно web-first; адаптивный веб покрывает 75%+ мобильного трафика; удваивает стоимость разработки | Responsive web; приложения — v2+ при доказанном спросе |
| Автоподнятие/репосты объявлений (bump/renewal) | Продавцы хотят «освежить» объявление | Это скрытое продвижение; на Craigslist-классifieds с этим борются (KSL: запрет репоста 14 дней) | Снятие с публикации → создание нового объявления (лимит 10 естественным образом ограничивает) |

## Feature Dependencies

```
[Admin: дерево категорий] ──requires──> [Admin UI / роль администратора]
[Admin: справочник городов] ──requires──> [Admin UI / роль администратора]

[Auth: регистрация/вход] ──requires──> (nothing; foundational)
[Профиль пользователя] ──requires──> [Auth]

[Listing CRUD] ──requires──> [Auth] + [Профиль] + [Дерево категорий] + [Справочник городов]
[Публикация с лимитом ≤10] ──requires──> [Listing CRUD]
[Search + фильтры + сортировка + пагинация] ──requires──> [Публикация] (индексируем только опубликованное)
[Страница объявления] ──requires──> [Публикация]
[Страница продавца] ──requires──> [Страница объявления] + [Профиль]

[Messaging] ──requires──> [Auth] + [Страница объявления] (контекст «по объявлению»)
[Уведомления о сообщениях] ──requires──> [Messaging] + подтверждённый e-mail из [Auth]
[Маскировка контактов в чате] ──enhances──> [Messaging]

[Снятие с публикации = hard delete] ──conflicts──> [Favorites/избранное], [История диалогов], [Search index]
    └── удалённое объявление разрывает ссылки из избранного, диалогов и выдачи — нужны решения (soft-ссылки, заглушки)

[Report abuse] ──requires──> [Auth] + [Страница объявления] / [Messaging]
[Admin: управление пользователями/контентом] ──requires──> [Report abuse] (источник сигналов)
```

### Dependency Notes

- **Listing CRUD requires дерево категорий и справочник городов:** обязательные поля объявления ссылаются на оба справочника — админ-каталоги должны существовать до пользовательских фич (влияет на порядок фаз roadmap).
- **Messaging требует страницу объявления:** диалог логично привязывать к объявлению (паттерн «per-listing conversation» — контекст не теряется); «написать продавцу» без объявления бессмысленно.
- **Уведомления усиливают Messaging:** без email-уведомления время ответа растёт с минут до дней — рынок этого не прощает.
- **Hard delete конфликтует с производными сущностями:** избранное, диалоги и поисковый индекс ссылаются на объявление; при удалении из БД нужны отдельные решения: каскад, заглушка «объявление удалено», удаление из индекса. Это архитектурное решение фазы planning, не фича.
- **Лимит 10 конфликтует со спам-стратегией дилеров:** именно поэтому лимит — часть анти-спам контура, а не просто ограничение.
- **Auth — фундамент всего:** регистрация/вход/сброс пароля должны появиться в первой пользовательской фазе, хотя PRD их явно не описывает.

## MVP Definition

### Launch With (v1)

Минимум для проверки гипотезы «частные объявления находят покупателя без коммерческого шума».

- [ ] Регистрация/вход/сброс пароля + подтверждение e-mail — без аккаунта не существует ни одна пользовательская фича
- [ ] Профиль (имя, телефон, e-mail) — из PRD
- [ ] Admin: дерево категорий (CRUD) — из PRD; скелет навигации
- [ ] Admin: справочник городов (CRUD) — из PRD
- [ ] Listing CRUD (заголовок ≤128, описание ≤512, цена, город, категория) — из PRD
- [ ] Публикация/снятие с лимитом ≤10 и hard delete — из PRD
- [ ] Search: полнотекстовый + фильтры (категория/город/цена) + сортировка (дата/цена) + пагинация — PRD заявляет поиск без деталей; без фильтров и пагинации поиск не живёт
- [ ] Страница объявления + страница продавца — точка входа в Messaging
- [ ] Messaging (диалог по объявлению, ≤512) + email-уведомления — из PRD + критический пробел PRD
- [ ] Фотография объявления (минимум 1) — **не в PRD, но настоятельно рекомендуется добавить на requirements**: единственная крупнейшая дыра против всех конкурентов
- [ ] Responsive web (мобильная адаптивность) — не в PRD, порог входа рынка

### Add After Validation (v1.x)

- [ ] Favorites/избранное — после того, как покупатели вернутся второй раз (триггер: repeat-визиты)
- [ ] Saved searches + уведомления о новых объявлениях по подписке — триггер: жалобы «просмотрел всё, жду нового»
- [ ] Report abuse + блокировка пользователей + admin-панель модерации — триггер: первый спам/скам
- [ ] Маскировка телефонов/ссылок в чате — триггер: первые случаи парсинга/спама через чат
- [ ] Счётчик просмотров объявления — триггер: продавцы спрашивают «кто-нибудь видит моё объявление?»
- [ ] Rate limiting / CAPTCHA на регистрацию и отправку сообщений — триггер: первые боты
- [ ] Быстрое действие «Продано» (снимает с публикации в один клик) — UX-обёртка над существующим механизмом

### Future Consideration (v2+)

- [ ] Гео-радиус поиска — только если справочник городов окажется недостаточен
- [ ] Мобильные приложения — при доказанном product-market fit и мобильном спросе
- [ ] SEO-страницы-лендинги категорий×городов (каталого-подобные) — при ставке на органический трафик
- [ ] Уведомления в реальном времени (WebSocket) вместо email-only
- [ ] Лёгкая верификация телефона (SMS) — только если скам станет системным

## Competitor Feature Analysis

| Feature | Avito (лидер RU-рынка) | Craigslist (США, минимализм) | Kleinanzeigen (Australia) | Our Approach |
|---------|--------------|--------------|--------------|--------------|
| Модель | Гипер-коммерциализированная: бизнес-аккаунты, платная доставка, продвижение | Минималистичная, полуденонимная, email-релей | Бесплатно для частников, платно для дилеров | Строго частные лица, бесплатно |
| Бесплатный лимит | 4 объявления/месяц в категории (жалобы пользователей) | Фактически неограниченно, авто-экспирация ~30-45 дней | Без жёсткого лимита | 10 активных одновременно — осознанный анти-спам барьер |
| Продвижение | Платные бусты, VIP, таргетинг — ядро монетизации | Нет | Платные «Top-Of-List» для частников | Нет никогда — равная видимость |
| Messaging | Чат в платформе + маскировка, «Avito Доставка» | Анонимный email-релей | Внутренний чат | Чат по объявлению + email-уведомления; маскировка в v1.x |
| Сортировка/выдача | Платно-взвешенные алгоритмы (предмет жалоб) | Хронологическая | Хронологическая + платные вставки | Прозрачная: дата/цена/релевантность, без оплаты |
| Photos | Обязательны фактически | Опциональны | Обязательны для большинства категорий | Рекомендуется как обязательное поле (решить на requirements) |
| Reviews/ratings | Есть (рейтинг продавца) | Нет | Есть (лёгкий) | Нет (anti-feature) — report + модерация |
